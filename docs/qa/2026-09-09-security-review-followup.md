## 第三份附件：12 项结论

1. canonicalPath 本身负责解析，不负责限制在“原始字符串范围”；真正的问题是调用者漏检解析结果，本轮已修复。
2. 临时目录例外不是允许 `/tmp/../../etc`；路径中的 `..` 有检查。允许系统临时目录的子目录、禁止临时目录本身，是避免破坏共享临时根目录的设计，不能按报告建议倒过来。
3. Clone 部分成立，但实际遗漏字段与报告不同，见上表。
4. `/api/wsdl/`、`/api/soap/`、`/api/ws/xml/` 均命中统一 license 网关，不存在所述绕过。
5. preview/extract 都要求 admin 是有意的本机文件能力边界，不是权限遗漏。
6. safePath 已经同时检查 cleaned 和 actual；该段报告引用了检查却又声称没有检查，是误报。本轮另外补强真正打开文件时的边界。
7. ownership 保存的是产物直接子项名称，不是把链接目标读入元数据；当前删除链接不会递归删除其目标。没有证据证明报告所述登记窗口直接形成越界，未把此项作为已证实漏洞。
8. 带时间戳不等于随机 nonce 可预测；额外随机源失败保护见上表。
9. iframe 中 location.origin 属于该文档自身，不是嵌入者的 origin；且响应设置 X-Frame-Options:DENY。该结论不成立。
10. WEB-INF/classes 正是 WAR 内的合法结构；移除 WebRoot 外壳并保留它是正常语义。
11. FTP 登录必须向服务提供凭据，请求体传输不自动等于写入日志。权限/TLS 验证已加固，但没有引入新的 FTP 凭据存储体系；远程部署仍需安全传输。
12. 从既有 tar 单独生成 ZIP 不必有原工程；输出敏感路径检查仍执行，缺 ProjectDir 本身不是绕过。

最后一段仅列出提交和审查范围，没有新增具体缺陷。

## 其它误报、取舍和验证边界

- ReadOnlyConfigured 的 JSON 往返丢失说法不成立：read_only 不省略，自定义 UnmarshalJSON 根据字段存在性恢复标记。production/默认只读是安全默认值，不改回更宽松策略。
- 大写盘符在原函数中已经检查；“只能识别小写”不成立。
- delete(map, 不存在的键) 合法；闭包、锁嵌套、全局 UI 状态并不能单凭存在就推断泄漏或死锁。未进行无证据的结构重写。
- 当前 Diff2Html 是仓库内静态文件，不是每次拉取未固定的 CDN 版本；恶意 script/img 输入检查通过。通用 unsafeHtml API 仍保留，但三处已确认的不可信插值已处理。
- Build+ZIP 在同一 HTTP 操作内共享一次确认授权，不是同一个令牌能发起两次独立请求；没有强行拆成两次用户确认。
- `?token=` 仍保留用于已有 SSE/下载兼容；未重构所有会话传递。开发者指定的 web-dir、本机浏览器状态仍属于可信本机配置，未增加签名系统。
- 这些防护不等同于承诺对具有同一用户文件写权限的持续恶意进程实现完整文件系统隔离；未实现跨所有发布步骤的目录事务沙箱。
