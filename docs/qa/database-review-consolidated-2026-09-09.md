## 初始附件中其余重点项

已处理：

- WITH 中写操作不再归类为普通查询。目前对 WITH 写语句明确拒绝，要求使用独立 DML；不是新增完整 CTE 写语法支持。
- 查询/批处理/脚本/网格/导入/提交回滚/事务状态使用服务端按用户划分的会话标识。本机关闭认证模式保持原有行为。事务 LOB 令牌不能跨用户使用。
- 生产环境加锁查询同样要求确认。前端写操作检查账号与数据源权限；服务端继续承担最终授权。
- 关闭页签等待回滚成功，失败保留页签与修改；正在执行的查询先取消。多页签并发关闭后重新确认索引与剩余数量。
- 会话事务数量与 MaxOpenConnections 联动；连接池大于 1 时为查询/元数据预留一个连接，单连接池限制为一个事务。
- Oracle q 引号、Oracle 普通字符串反斜杠与 MySQL # 注释按方言处理；PL/SQL normalize 保留 END 分号。未闭合 q 字符串不再切出内部伪语句。
- CSV 空白行存在真实的残留列问题，已修复；报告所称 splice 返回数组与原数组共享引用不成立。
- 深链接只载入 SQL，不自动执行；编码参数过长时只保留数据源并提示通过文件传递 SQL。
- 浏览器内存导出限制 64MB，流式累计超限取消读取；离开路由取消导出，支持文件流时直接写盘。
- CSV/XLSX 保护以减号开始的表达式，保留合法负数；导出移除 LOB token。
- Redis 列表/有序集合范围最多 500 项，XRANGE 必须指定不超过 500 的 COUNT。通用命令入口拒绝无界 HGETALL，并提示 HSCAN 分页。
- 导入 JSON rows 同样校验每格 256KB、总文本 8MB、列数限制。原 HTTP 请求体已有 12MB 上限。
- 错误脱敏覆盖数据库与 SSH 密码；凭据存储真实故障时返回通用错误，未保存凭据不作为故障。脚本/网格/导入失败审计同样脱敏。
- 极端分页在 SQL 发往数据库前拒绝，偏移上限为 1000 万行。
- 批处理跳过 COMMIT;/ROLLBACK;，不会因尾部分号绕过控制语句检查。

不成立、已有防护或需区分的结论：

- `!user` 对应项目允许关闭认证的本机模式，不能无条件改为禁止，否则破坏既有模式；启用认证时由 HTTP 中间件和 requireAdmin/只读策略保护。
- ValidateReadOnlySQL 已遍历拒绝写入关键字，并非 WITH 无条件放行；本次修复的是较宽松 ClassifySQL 的分类路径。
- rollbackPendingEdits 原本就在 await 成功之后清理脏数据，断网会进入 catch；真正有问题的是关闭页签时忽略回滚失败。
- 历史已按 source key 读写，清空当前 history 不会清空其他数据源；gridContext 同时拥有 table 和 sessionId。
- UTF-8 字节循环会写入每个连续字节，并非只写首字节，不能据此断言中文截断。
- 环境/只读复选框会由 syncSourceAdvanced 同步属性；HTML 初始未写 checked/selected 不代表最终值错误。
- Oracle 不强设只读事务有现存 ORA-01466 兼容性说明，且查询事务在请求末回滚，不盲目添加额外 SET TRANSACTION。
- 大文本不高亮、连接空闲时间、JSON/LOB 有界读取属于性能/驱动边界，不能直接当作安全漏洞删除。
- NDJSON 已按完整换行缓冲半包，并在外层处理异常；失败时保留已接收行，不是报告描述的“半包直接 JSON.parse 后丢光结果”。
- 请求恢复只重试后端明确标记且尚未输出的请求。数据库写操作没有被任意改成自动重试。
- 本地 SQL 历史/草稿持久化、可编辑 CHECK 表达式、DDL 非原子提交有明确产品/数据库语义。本次不擅自删除这些功能或承诺通过前端解析器实现完整 SQL 沙箱。
