## 1. 目标与审查原则

对批次 A+B 触动的 UI 做**有证据的视觉审查**：截图矩阵（主题 × 页面 × 状态 × 视口）+ 逐图走查打分。原则：

1. **5 套主题全覆盖**：dark / light / green / hc / xianxia（切换用 `helpers.setTheme`，变量对照 `tests/THEME-VARS.md`）。
2. **Win7 兼容**：新增 UI 不得依赖彩色 emoji（B 批 715424b 已把按钮 SVG 化），图标必须是 SVG 且 5 主题下对比度可辨。
3. **状态优先于页面**：空态/有数据/错误态/加载态/悬停/弹层，比页面数量更重要。
4. **基线对比**：与 `docs/screenshots/`（README 用图）及 git 历史截图 diff，发现非预期视觉漂移。

## 4. 逐图走查清单（每张截图按此 8 项打分 0/1）

1. **对齐**：卡片/表单/表格网格对齐，无 1px 错位。
2. **溢出**：长文本（任务命令、宠物名 16 字上限、cron 表达式、URL）不溢出容器，省略号/换行策略合理。
3. **间距**：与既有页面间距体系一致（8px 基准），新增元素不挤不空。
4. **对比度**：正文/按钮文字 ≥ 4.5:1（hc 主题必须，其余主题目测+抽测）；状态色（成功/失败/running）5 主题可辨且不单依赖色相。
5. **主题变量**：新 CSS 只用 `tests/THEME-VARS.md` 已有变量（grep `web/style.css` diff 中新增选择器，发现硬编码 hex 记 P2）。
6. **图标**：全部为 SVG（无 emoji 依赖），风格（线宽/圆角）与 icons.js 既有图标统一。
7. **反馈态**：按钮 hover/active/disabled、加载 spinner、错误红——三态齐全。
8. **中文排版**：标点不顶行、按钮文案不换行、数字/英文不断词错位。

## 5. 实施方式

1. 复制 `tests/e2e/screenshot-themes.js` → `tests/e2e/screenshot-review-2026-08.js`，按 §2 矩阵扩展：
   - `PAGES` 增加 `tasks`、sponsor 双 tab 状态、http WS 面板等；
   - 用 `helpers.setTheme` 循环 5 主题；前置状态通过 API 构造（`POST /api/pet/enable`、`POST /api/tasks` 造 3 条、mock sponsor 数据）；
   - 每图命名 `03-{page}-{theme}-{state}-{viewport}.png`。
2. 状态构造顺序：先 API 造数据 → 等 UI 轮询刷新（running 态等 3s）→ 截图。
3. 基线对比：与 `docs/screenshots/themes/*.png` 同名页面对比（像素 diff 工具不限，人工并排亦可），记录**非预期**变化（预期内变化 = 新卡片/新 tab/新按钮）。
4. 逐图按 §4 打分，问题图附 200% 局部放大截图。
