## #20 配置持久化（重启 + 切 tab 不丢）

### 症状
> "重启服务运行 exe，功能全部丢失了"
> "切换 tab 栏，也会丢失配置"

### 根因排查（按时间顺序）

1. **后端 PUT → GET 已正确**（`docs/v0.5-p0-diagnosis.md` 实测）：
   ```
   PUT /api/admin/servers {encoding:gbk} → ok
   GET /api/admin/servers → encoding:gbk
   磁盘 grep encoding: → gbk
   kill + 重启 → GET 仍 gbk
   ```
   `Manager.Replace` 走 `Defaults → Validate → writeYAMLAtomic(.tmp+rename) → 内存替换`，逻辑没毛病。

2. **前端 renderConfig 重新跑 + GET 拿新值覆盖内存里 state**：
   ```js
   // 改前：state 在 renderConfig 闭包里
   function renderConfig(view) {
     const state = { systems: [], dirty: false, ... };
     // 每次切 tab → view.innerHTML = '' → renderConfig 重新跑 → state 是新的
     // 把后端 GET 拿到的旧 systems 覆盖掉用户内存里未保存的改动
     api('GET', '/api/admin/servers').then(info => {
       state.systems = info.systems;  // ← 覆盖用户的未保存编辑
       ...
     });
   }
   ```
   `app.js:navigate()` 在 hashchange 时先 `view.innerHTML = ''` 然后调 `routes[name](view)`，
   所以 `renderConfig` 每次都跑、闭包里的 state 每次都是新的。

3. **input 事件 markDirty 不重渲染** —— 这部分是对的（用户编辑 → markDirty → renderEditor 在 markDirty 后**没有**被调，所以 input 焦点不丢）。

### 修复

#### A. 切 tab 不丢
`web/pages/config.js:24-37` — state 提到模块级：
```js
if (!OTB.state.configEditor) {
  OTB.state.configEditor = { systems: [], app: null, ..., loaded: false };
}
const state = OTB.state.configEditor;
```

`web/pages/config.js:348-365` — 加载逻辑：
```js
if (state.loaded && state.systems) {
  // 已加载过：直接 render，不再 fetch
  renderApp(); renderSearch(); renderEditor();
  maybeShowBanner({ app: state.app });
} else {
  api('GET', '/api/admin/servers').then(info => {
    state.systems = JSON.parse(JSON.stringify(info.systems));
    state.loaded = true;
    ...
  });
}
```

切 tab 回来时 `state.loaded === true`，**跳过 GET**，直接复用内存里 state.systems。
用户未保存的编辑（脏数据）跨 re-render 保留。

#### B. 离开页面前 confirm
`web/app.js:25-38` — `navigate()` 检测 `OTB.state.unsavedConfig`：
```js
if (state.unsavedConfig) {
  const targetHash = (location.hash || '#/home').replace(/^#\//, '');
  const onConfig = (targetHash === 'config' || ...);
  if (!onConfig && !window.confirm('系统配置有未保存的改动，确定要离开吗？\n（点"取消"留在配置页）')) {
    if (history && history.replaceState) {
      history.replaceState(null, '', '#/config');  // 改回 hash 保持链接一致
    } else {
      location.hash = '#/config';
    }
    return;  // 阻止 re-render，留在配置页
  }
}
```

`markDirty()` 时设 `OTB.state.unsavedConfig = true`，`doSave` 成功后清掉。
这给用户一个"误点其他 tab 时不会丢未保存改动"的安全网。

#### C. 重启不丢
后端本来就 OK（PUT → 磁盘 + 内存 → 重启读磁盘全部一致）。
这次新加 `TestReplace_FullRestartRoundTrip` 5 阶段端到端单测防回归：
```
阶段 1: Load(初始 yaml) → Manager
阶段 2: encoding utf-8 → gbk → Replace
阶段 3: 模拟 kill + Load(path) → Manager（验证 gbk 已落盘）
阶段 4: host 改 10.0.0.42 → Replace
阶段 5: 再 kill + Load(path)（验证 host + gbk 都还在）
```

### 验证

| 测试 | 断言 |
|---|---|
| `testConfigStatePersists` | 首次 render GET=1，编辑后切回 GET 仍=1，state.systems.length=2（保留编辑）|
| `testConfigSaveClearsDirty` | doSave 成功后 dirty=false, unsavedConfig=false, 切回不 GET |
| `TestReplace_FullRestartRoundTrip` | 5 阶段全链路，host 和 encoding 都跨重启保留 |
| 端到端 | 18099 端口 PUT → 磁盘 yaml 内容正确 → kill + restart → GET 一致 |

## #6 GBK 编码保存

### 症状
> "在日志目录编辑页选 GBK → 保存 → 刷新页面回来还是 utf-8"

### 根因排查

1. **后端正常**（同上：`docs/v0.5-p0-diagnosis.md` 实测 PUT gbk → GET gbk → 磁盘 gbk）。
2. **前端 `option.selected = true` 不可靠**：在某些浏览器 / 边角 case 下，
   detached option 设置 `selected = true` 后再 append 到 select，
   `select.selectedIndex` / `select.value` 不一定更新到那个 option。
3. **PUT body 不丢字段**：后端用 `json` 标签序列化 `LogDirEntry.Encoding`，
   前端 `ld.encoding = encSel.value` 直接写在 state 上，PUT 时随 `state.systems` 一起发。

### 修复

`web/pages/config.js:283-294` — 显式设 `encSel.value` 同步 `ld.encoding`：
```js
const encSel = el('select');
[
  ['utf-8', 'utf-8（默认）'],
  ['gbk', 'gbk（远程是 GBK）']
].forEach(([v, t]) => {
  encSel.appendChild(el('option', { value: v, text: t }));
});
// 显式设置 value，比 option.selected = true 更可靠
const wantEnc = (ld.encoding || 'utf-8').toLowerCase();
encSel.value = (wantEnc === 'gbk') ? 'gbk' : 'utf-8';
if (ld.encoding !== encSel.value) ld.encoding = encSel.value;
```

后端 `Defaults()` 已经归一 `GBK` / `gb18030` → `gbk`，
`Validate()` 已经拒非法值（`shift-jis` / `EUC-JP` 等），
所以"前端 PUT 什么 → 磁盘存什么 → GET 拿回什么"整条链是 OK 的。

### 验证

| 测试 | 断言 |
|---|---|
| `testConfigEncodingGBK_Preserved` | 模拟"服务器返回 utf-8 + gbk 两条 log_dir"，切 tab 回来两条 encoding 都在；模拟用户改 utf-8→gbk 后 PUT，PUT body 含 `encoding:gbk` 不丢字段 |
| `TestReplace_GBKEncoding_Preserved` | 改 gbk 后内存/磁盘/重载三处都是 gbk；`GBK` / `gb18030` 都归一到 `gbk` |
| `TestReplace_UTF8Encoding_StillWorks` | gbk → utf-8 反向 round-trip 也通 |
| `TestReplace_RejectsBadEncoding` | `shift-jis` 被拒（带 `encoding` 错误信息），磁盘/内存均不变 |
| 端到端 | 18099 PUT 把 utf-8 改 gbk → 磁盘 yaml = `encoding: gbk` → kill + restart → GET 仍 gbk；shift-jis 返回 400 |

## 风险与权衡

| 风险 | 缓解 |
|---|---|
| 切 tab 回来不 fetch → 用户看到的可能是脏数据 | doSave 成功后 `loaded=true, dirty=false`，下次 re-render 仍用新 state.systems；如果用户点"放弃改动"才重新 fetch（doReset 走 GET）|
| confirm 弹窗可能打扰用户 | 离开**配置页且有未保存改动**才弹；在配置页内导航不弹；保存成功后不弹 |
| `encSel.value = 'gbk'` 后 `ld.encoding = encSel.value` 强行规一大小写 | 后端 `Defaults` 也做同样规一，行为一致；非法值走 Validate 报错而不是静默改 utf-8 |
| 旧 PUT 接口契约 | handlers_admin.go 一行没改，curl PUT 行为完全不变 |
