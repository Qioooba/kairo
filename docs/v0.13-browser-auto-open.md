# v0.13 — 自动打开浏览器 + 记住上次浏览器

> 状态：✅ 已合并到 main（待发版打包）
> 配合主版本：v0.13（见 VERSION）

## 用户视角变化

| 之前 | 现在 |
| --- | --- |
| 双击 exe 不弹窗，要手动浏览器访问 `http://127.0.0.1:18080` | 双击 exe 自动开浏览器（默认 true） |
| Win 下用 rundll32 调默认浏览器 | 装了 Chrome 就用 Chrome；没装走默认浏览器 |
| 每次都重新探测浏览器 | 记住上次用的浏览器，下次直接复用 |
| 没有"清掉浏览器偏好"的办法 | `kairo.exe --reset-browser` 一行命令重置 |

## 技术要点

### 1. `internal/browserpref` 新包

持久化"上次用什么浏览器打开"到 `data/browser_state.json`：

```json
{
  "kind": "chrome",  // 或 "default"
  "path": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
  "updated_at": "2026-07-07T22:51:00+08:00"
}
```

- 原子写：先写 `.tmp` 再 `os.Rename`，Win 上 rename 偶发被挡住时 100ms 后重试一次（跟 credentials.saveFile 同套路）
- `Read()` 文件不存在 → 返回 `(nil, nil)`，不报错（首次启动是正常情况）
- `Reset()` 文件不存在 → 幂等（`--reset-browser` flag 反复调用无副作用）
- `ReadUnknownKind()`：未来加新枚举值时老 state 自动回退 default，不阻塞"打开"

### 2. `internal/sysutil.FindChrome()`

Win 下的 Chrome 探测，Win7/10/11 一致：

1. **常见路径**（`os.Stat` < 1ms，最高命中率 95%+）：
   - `%ProgramFiles%\Google\Chrome\Application\chrome.exe`
   - `%ProgramW6432%\Google\Chrome\Application\chrome.exe`
   - `%ProgramFiles(x86)%\Google\Chrome\Application\chrome.exe`
   - `%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`
2. **注册表兜底**（< 5ms，处理"装在非标准路径"的边角用户）：
   - `HKLM\SOFTWARE\Google\Chrome\Application\path`
   - `HKLM\SOFTWARE\WOW6432Node\Google\Chrome\Application\path`（32-bit on 64-bit）

实现走 `syscall.NewLazyDLL("advapi32.dll")` 直绑 RegOpenKeyExW / RegQueryValueExW，**不依赖 `golang.org/x/sys/windows/registry`** —— 跟 `autostart_windows.go` 同套路，保持 Go 1.20 兼容性。

非 Win 平台：stub，返回 `("", false)`。

### 3. `main.go` 决策链

```
启动 → openBrowser(url)
   ├─ 1) 读 state（< 1ms）
   │     ├─ state.Kind=chrome + path 文件仍在 → exec(state.Path, url)  ✅ remembered=true
   │     └─ 没有 / 失效                           → 进入 2
   │
   ├─ 2) 探测链
   │     ├─ Windows + Chrome 已装 → exec(chrome.exe, url)         remembered=false
   │     ├─ Windows 默认浏览器    → rundll32 url.dll,FileProtocolHandler
   │     ├─ macOS                → open url
   │     └─ Linux                → xdg-open url
   │
   └─ 3) 启动成功 + !remembered → 写 state
```

### 4. `config.yaml` 默认值变更

```yaml
app:
  auto_open_browser: false  # → true
```

`AutoOpenBrowser` 字段类型从 `bool` 改成 `*bool`，新增 helper `AutoOpenBrowserEnabled()`：

- 字段未配置（nil，老 config 升级上来）→ **默认 true**（与新装机行为一致）
- 显式 `auto_open_browser: true` → true
- 显式 `auto_open_browser: false` → false（用户主动关，UI 上尊重选择）

语义跟 `FreeFileBrowserEnabled` 一致。

### 5. `--reset-browser` flag

```bash
kairo.exe --reset-browser
```

独立命令行路径：解析 cfg → `browserpref.Reset()` → 退出。不进入主流程。

## 性能 / 资源

- 启动路径：`Read()` ≈ 1ms（一个小 JSON file）
- 探测路径：`os.Stat` 常见路径 ≈ 1ms；命中就 1ms，没命中读注册表 ≈ 5ms
- **新功能总开销：< 10ms / 启动**，跟现有 `rundll32` 一档
- 本进程：浏览器 exec 后 Wait 在 goroutine 里，不阻塞主流程
- state 文件：< 1KB，对 storage 几乎可忽略

## Win7 / Win10 / Win11 兼容性矩阵

| 维度 | Win7 | Win10 | Win11 |
| --- | --- | --- | --- |
| 常见 Chrome 路径 | ✅ 同一形态 | ✅ | ✅ |
| `os.Getenv("ProgramFiles")` | ✅ | ✅ | ✅ |
| `os.Getenv("ProgramW6432")` | ✅（x64 edition 起） | ✅ | ✅ |
| `RegOpenKeyExW` Unicode | ✅（默认 Unicode） | ✅ | ✅ |
| `HKLM\SOFTWARE\WOW6432Node\...` | ✅（x64 edition 起） | ✅ | ✅ |
| `os.Rename` atomic write | ✅（100ms retry 兼容） | ✅ | ✅ |
| 命令行 `--reset-browser` | ✅ | ✅ | ✅ |

**Chrome 109 是最后一个支持 Win7 的版本**（Chrome 110+ 起官方放弃 Win7/8）。Win7 上用户装的 Chrome 路径跟 Win10/11 完全一致，探测不动旁路即可。

## 兼容性：Go 1.20 build tag

- 没有引入 `golang.org/x/sys/windows/registry`（项目 vendor 不包含，刻意避免）
- 全用现有 `syscall.NewLazyDLL` 路径，跟 `autostart_windows.go` 一致
- Win7 amd64 build 仍走 `Go 1.20.x` + `scripts/build_windows_amd64_win7_go120.sh`，新代码不破坏
