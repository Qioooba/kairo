# v0.5 P0 bug 诊断报告（root session 实测）

> 测试时间：2026-06-23 12:55-13:00
> 测试方法：起 OpsToolbox_mac + mock_sshd，curl 走查

## 后端实测结论：4 个 bug 都不是后端的问题

### #20 配置丢失 → 后端 PUT 持久化正常
**实测**：
1. `PUT /api/admin/servers` 改 encoding=utf-8 → gbk → 返回 `{"ok":true,"path":"/Users/qi/Documents/spaces/ops-toolbox/config.yaml"}`
2. `GET /api/admin/servers` 返回 `encoding: gbk`
3. 磁盘 `grep encoding:` 也是 `gbk`
4. **kill 进程 + 重启** → GET 仍返回 `gbk`

→ PUT → 内存 + 磁盘 + 重启 三层都 OK。`Manager.Replace` 走的是 `Defaults → Validate → writeYAMLAtomic(.tmp+rename) → 内存替换`，逻辑正确。

→ **#20 的真实问题在前端 UI 状态丢失**（用户感觉的"功能丢失"），不是后端。

### #6 GBK 保存后还是 UTF-8 → 后端正确
**实测**：PUT 改 gbk 后 GET 返回 `gbk`，磁盘也是 `gbk`。**后端没问题**。

→ **#6 真实问题可能**：前端 PUT 时 `encoding` 字段没传对（前端的 encSel change → ld.encoding = encSel.value → markDirty → renderEditor；renderEditor 重建时 encSel 重新创建，从 ld.encoding 取 → 显示 GBK → 这看着也对）。

→ 唯一的可能是：**用户的 GBK 修改没真的点保存按钮就切了 tab**（dirty 但未持久化 → 切 tab 时前端 reload → 重新 GET → 内存里还是 utf-8）。这是前端 UX bug（#20 的"切换 tab 丢失"），不是 #6 后端 bug。

### #8 日志搜索无效 → 后端完全 OK
**实测**：
```
POST /api/logs/search/multi { system, servers, dir, files:2, query:"INFO", username:"test" }
→ ok_count: 1, hits: 4 条 INFO 命中（SystemOut.log line 2/4/5/...）
```

后端能正常搜到匹配。

→ **#8 真实问题**：前端 websphere.js 怎么发请求没接对（参数缺失/字段名错）。需要查看 websphere.js 的调用代码。

### #7 多服务器点列出文件只展示一台 → 后端按 server 单查
**实测**：`POST /api/files/list { server: "mock-node-1", path: ... }` 只返回 mock-node-1 的目录条目（10 条）。**handler 设计上就是单 server**（line 107：`s.cur().FindServer(req.System, req.Server)`）。

→ **#7 真实问题**：如果前端想"多服务器列出文件"需要在前端循环调用 N 次（每个 server 一次），或者后端支持 `servers []` 数组。
→ 后端当前不支持多 server list，前端如果一次发一个 server 就只能展示一台。**修复方向**：把 `/api/files/list` 改成支持 `servers []` 或在前端循环。
